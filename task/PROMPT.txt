开发一个离线工具，分析网关与业务服务对同一JSON报文解释不一致造成的授权风险。

请从空目录实现以下可运行工具。环境为 Windows、Python 3.12、仅CPU；不使用Docker或真实外部服务。除题面明确允许的cryptography外只用标准库。输入样例、模拟组件和测试数据由你在项目内构造，不存在另行提供的附件。

核心要求：
1. 实现保留重复键和原始数值文本的解析树，不得先用普通字典丢失信息；支持UTF-8、转义代理对与精确十进制数，拒绝无效Unicode和超深嵌套。
2. 提供first-key、last-key两种对象策略，以及精确整数和IEEE754数值策略；针对tenant、amount、role三条受保护路径计算语义差异，区分仅序列化不同与实际授权数据不同。
3. 生成安全规范化表示：受保护对象重复键拒绝、数值按无损范围约束、键排序并保留数组顺序；签名前后业务读取必须使用同一个已验证树。流式输入的错误偏移以字节计。本题规范化采用UTF-8、对象键按Unicode码点排序、无多余空白，数值限制为绝对值不大于2^53-1的整数，负零统一为0；所有层的重复键均拒绝，非整数拒绝。

必须覆盖的验收场景：重复键嵌套、转义后同名键、2^53附近金额、负零和代理对；验证合法报文规范化幂等，危险报文不能通过重排键逃逸。

交付源代码、README、样例及自动化测试。提供 python -m solution --input cases.json --output result.json 和 python -m unittest discover -s tests -v 两个入口；cases.json可引用项目内源文件或二进制样例。输入输出schema、错误码及未写明的非安全性细节自行设计并完整说明，不能放宽上述要求。测试必须断言具体结果、状态或证据，不能只打印成功；固定种子可重放。所有操作局限在项目测试目录和本机模拟服务。
